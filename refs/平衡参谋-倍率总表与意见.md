## 3.1 三层 + 一层的定义

```
最终单层倍率 = ①属性层 × ②极性层 × ③无条件层
① 属性层（表 3.2）
     材质属性 != null 且 == 记录属性        → ×2.00
     材质属性 != null 且 记录属性 ∈ 交叉表  → ×1.50
     其它（含材质属性 == null 的铁/金/钻石）→ ×1.00
     ☆ 再叠一层：若记录属性 == 挑战 → 再 ×1.50，但只有绿宝石的这层 != 1.00
② 极性层（表 3.3）  正 = 升华那一侧，负 = 沉坠那一侧
③ 无条件层（表 3.4）只有绿宝石 ×1.20
```

`positive` 这个入参来自 **记录的正面占比 `ratio`（>0.5 才算正）**，不是从属性推的 —— `RitualEffects.java:178-179` 把 `positive`（即"这是升华还是沉坠"）直接传进去。**一条记录的属性不决定它是正是负。**

# §6 全链路算例（从一条记录 → 注入 → 绽裂）

## 6.1 公式（照 `RitualEffects.java:126-183` 逐行抄）

```
idx        = 书里第一条【未消耗】的记录（从头找，先记的先用）   ← :238-245
amount     = 8 + floor(ratio × 4) × 8          （档位 0/1/2/3 → 8/16/24/32）  ← GuideBookItem:393
share      = 升华 ? ratio : (1 − ratio)                                        ← :134
total      = round(amount × share)                                             ← :135
if total ≤ 0 → 【失败】消耗该记录、不注入、不启动动画                            ← :144-162
pref       = mult(外围特性, 外围属性, 记录属性, positive)
           × mult(中心特性, 中心属性, 记录属性, positive)                       ← :175-182
lossss     = 外围注入比例 × 中心注入比例 × pref     ← :182
injected   = max(1, round(total × loss))          ← :183   ★ 有 1 点下限
```

**三个独立因数，缺一不可**（`RitualEffects.java:230-233` 的提示也把它们拆成三段显示）：
`外围 ×0.50~0.90` · `中心 ×0.50~1.00` · `偏好 ×0.64~16.00`

**外围可用材质是受结构限制的**（`RitualStructure.java:206-217`）：

| 仪式 | 外围种类 | 外围等级 | 外围注入比例 |
|---|---|---|---|
| **升华** | `WOOD` / `NETHER_WOOD` / `CHORUS` | 0 / 1 / 2 | **0.50 / 0.75 / 0.90** |
| **沉坠** | `COBBLE` / `NETHER_ROCK` / `END_ROCK` | 0 / 1 / 2 | **0.50 / 0.75 / 0.90** |

> ⚠️ **外围永远吃不到等级 3 的 1.00** —— 因为 3 级只有钻石和紫珀砖，两者都不在木/石类里。**外围的注入比例上限就是 0.90。**

**中心可以是任意 19 种之一**（`RitualStructure.match` 只要求"中心是雕像 + 台座上有法杖"）。

## 7.4 是否存在"失控组合"

**有，但只有一个，而且非常极端：外围 4× 紫颂花 + 中心 紫颂花 + 空无记录。**

原因链：
1. **紫颂花同时是"木类外围"和"空无属性"** —— 它是唯一一个既能摆进升华结构、又能与空无记录构成 ×2.00 同类的材质。
2. 空无 ↔ 霜寒是交叉对 → 霜寒记录也吃 ×1.50。
3. 于是偏好可以做到 `4.00 × 4.00 = 16.00`，而升华为 0.90 × 0.90，**总值 12.96**。
4. 对比第二集团（下界原木 + 下界原木 + 下界记录）只有 **5.062** —— **2.56 倍断层**。

具体后果：
- 一条 32 点的空无记录 → **415 点** 注入。**一条记录就能把灵魂杖（128）冲爆 3.2 倍**，直接满足绽裂入场券。
- 若外围与中心都用紫颂花，**4 尊外围雕像只要 4 个紫颂花方块**，采集成本极低（末地一找一大片）。
- 反向验证：如果用下界原木，同样一条记录只能给 162 点。**用不用紫颂花 = 2.56 倍差距，且没有任何额外成本。**

**第二个不那么极端但同样要注意的点**：`Math.max(1, …)` 的 1 点下限意味着"**失败也有保底 1 点**"。结合 §7.1 的"0 点失败会烧掉记录"，**1 点注入比 0 点失败好，但两者观感几乎一样**（都是"什么都没发生"），玩家难以分辨是"运气差"还是"结构摆错了"。

## 8.3 经验转换效率

代码链（`RitualEffects.java:305`、`:321`、`:342`）：

```
心绪总量 = round(法杖含量 × 3.0)
加成后   = round(心绪总量 × 外围偏好)          // 外围偏好 0.50 ~ 4.00
每份     = 加成后 // (正面 6 / 负面 4)
装下     = Σ min(每份, 100)                    // 每类上限 100
经验     = (每份 × 份数 − 装下) ÷ 3            // 整数除法
```

**当存储全满时**（`每份 > 100`，即正面 `含量 > 200`、负面 `含量 > 133`）：

> **经验 ≈ 法杖含量 × 外围偏好 ÷ 3**，即 **经验 : 法杖含量 ≈ 1 : 3（无偏好）到 4 : 3（满偏好）**。

**注意这里没有 33 % 这个数** —— `×3` 和 `÷3` 互相抵消了，剩下的唯一变量是**外围偏好**。
换句话说：**绽裂把"多少点情绪"直接变成"多少点经验"，比例是 1:1（无偏好）到 1.33:1（满偏好）。**

对照：**烧掉一条记录** + **30 秒** + **5 尊雕像结构** 换来的法杖含量，最多 **415 点** → 单次绽裂最多 **≈138 点经验**（1 次绽裂，外围紫颂花偏好 ×1.33 的情况）。
而**正常玩（存储没满）一条记录能产生的经验是 0**。

# §9 平衡意见（参谋视角）

> 每条给**把握程度**：高 = 有代码事实支撑 / 中 = 推理但未见作者意图 / 低 = 依赖作者未公开的取舍。

## 9.1 明显不合理的数值区间

### ★★★ 问题 1：紫颂花是"唯一的孤儿外挂"，断层 2.56 倍（把握：**高**）

**事实**：`chorus` 是**唯一**同时满足"属于升华合法的木类"且"属性 = 空无"的材质。
空无 ↔ 霜寒是交叉对，于是：
- 空无记录：外围 4.00 × 中心 4.00 = **16.00**
- 霜寒记录：外围 3.00 × 中心 3.00 = **9.00**
- 其它任何外围（下界原木 3.00、木头 2.50）：最好只有 `3.00 × 3.00 = 9.00`

**后果**：14.5 级升级后，**升华的"最优解"永远是紫颂花**，没有任何取舍。
且"用不用紫颂花"= 2.56 倍注入差，**玩家的全部决策被压缩成"我有没有紫颂花"**。

**建议改法（三选一，按推荐度排序）**：

| 方案 | 具体改动 | 效果 |
|---|---|---|
| **A（推荐）** | `CHORUS` 正面 2.00 → **1.60**，负面 1.50 → **1.20**；给 `PURPUR` 正面 1.00 → **1.20**（补偿它 3 级只有 32 容量） | 紫颂花空无记录变 `0.90×0.90×(3.20×3.20)=8.29`，与下界原木的 5.06 拉近到 1.64 倍 |
| B | 把紫颂花的属性从 `VOID` 改成 `null`（走无条件增益） | 立刻消除"同类×同类"的 16 倍，但紫颂花失去属性身份，和末地设定冲突 |
| C | 让 `NETHER_WOOD`/`WOOD` 也能吃到交叉（例如让"自然"也进交叉表） | 治标，会让自然属性从"最容易获得"变成"也最强"，与 `EmotionAttribute.java:34` 的设计意图冲突 |

**我的数字建议（方案 A 的完整版）**：
```
CHORUS   正面 2.00 → 1.60     负面 1.50 → 1.20      （保留"最强木头"身份，不再断层）
PURPUR   正面 1.00 → 1.20     负面 1.75 → 1.60      （3级/32容量需要补偿）
END_ROCK 正面 1.00 → 1.10     负面 1.75 → 1.65      （末地石头略降，与下界岩石 1.50 拉开但不过分）
NETHER_ROCK 正面 0.75 → 0.85                        （正面不该被"石头不该给正面"压这么低）
```
改完后最大倍率：`0.90 × 1.00 × (3.20 × 1.60) = 4.61`（外围末地岩石+中心紫颂花的空无记录 → 单条 32 点记录 147 点）。
新断层 = 4.61 / 5.06 ≈ **0.91**（不再是断层）。

### ★★☆ 问题 2：升华与沉坠不对称，沉坠天生弱 15 %（把握：**高**）

**事实**：把双侧平均最好的组合列出来：

| 仪式 | 最优组合 | 偏好乘积 | 总倍率 | 32 点记录注入 |
|---|---|---|---|---|
| 升华 | 紫颂花 × 紫颂花 | 4.00 × 4.00 = 16.00 | 12.960 | 415 |
| 沉坠 | 末地岩石 × 紫珀砖 | 3.50 × 3.50 = 12.25 | 11.025 | **353** |

根因：木类外围的正面峰值（紫颂花 2.00）> 石头类的负面峰值（末地岩石 1.75），而**两者的"属性层"都能吃满 ×2.00**，所以差距直接来自极性层。
更糟的是**「下界」组合两边完全一样**（下界原木 1.50 / 下界岩石 1.50），但**升华为 0.75×0.75，沉坠为 0.75×0.90**（因为下界砖是 2 级、容量 40，能做中心；而对应的"下界原木类 2 级"不存在）。

**建议**：把 `END_ROCK` 负面从 1.75 提到 **1.80**，或把 `CHORUS` 正面从 2.00 降到 1.75（与问题 1 的改法合并处理）。
**目标**：两个仪式的最大倍率落在同一区间（我建议都收在 **8.0–10.0**，对应 32 点记录注入 256–320 点）。

### ★★★ 问题 3：灵魂雕像是一个"数值陷阱"（把握：**高**）

**事实**：`soul` = 等级 0（注入 **50 %**）+ 容量 **128**（全场最高）+ 属性空无 + 特性中性。

这是**自相矛盾**的一行：它想当"大容量容器"，但**注入效率全场最低之一**，导致它装满的代价是别人的 2 倍。
**而且它作为中心时注入比例 0.50，是所有中心里最低的一档**（与泥土/木头/圆石并列）——
**玩家花了 128 容量的期待，换来的是每次注入打对折。**

更微妙的是它**反而是绽裂的最佳载体**（容量越大，能积累的情绪越多才越容易超容量）：
- 用泥土杖（容量 8）：任何一次注入（哪怕 1 点）都超容量 → 绽裂立刻可用，但心绪总量只有 `9×3 = 27`。
- 用灵魂杖（容量 128）：要攒到 **129 点** 才能绽裂 → 需要 1–4 条记录，但一次能炸出 387 点心绪。**而 §8.2 显示 387 < 600，照样装得下、经验为 0。**

**建议（把握：中，因为取决于作者想让灵魂干什么）**：
- 如果灵魂是"容量专精"：`capacity 128 → 96`，`tier 0 → 1`（注入 50 % → 75 %）。代价是容量优势变小，但至少不自相矛盾。
- 如果灵魂是"高阶容器"：`tier 0 → 2`，容量 128 → 160。**但必须同时压低它在绽裂里的优势**（见 9.3）。
- **最省事的改法**：只把 `tier 0 → 1`。容量 128 保留。这样灵魂从"下位陷阱"变成"中期可用的大泵"，且不动数据结构。

### ★★☆ 问题 4：铁完全被金支配，泥土完全被木头支配（把握：**高**）

**铁的支配链**（全部同属性，只看数值）：

| | 等级 | 容量 | 无条件乘数（正/负） |
|---|---|---|---|
| 铁 | 2 | 32 | 1.05 / 1.10 |
| 金 | 2 | **40** | **1.25 / 1.15** |

铁在**等级相同、容量更小、两个方向的乘数都严格小于金**。金只需要 9 个金锭（一个方块）—— 这不是"便宜换弱"，这是**纯支配**。

**建议**：铁要么降级到 1 级（容量 24，乘数 1.05/1.10 保留，成为"便宜的 1 级万能中心"），要么把乘数提上去（**1.20 / 1.25**，让铁的负面比金高，形成"铁偏负、金偏正"的分工）。

**我倾向后者**（把握：中）：

```
METAL_IRON   正面 1.05 → 1.20    负面 1.10 → 1.25     （铁 = 便宜、偏负的万能泵）
METAL_GOLD   正面 1.25 → 1.25    负面 1.15 → 1.05     （金 = 偏正，与铁错开）
```

**泥土的支配链**：`dirt` = 0 级 / 容量 8 / 双面 0.80；`wood` = 0 级 / 容量 16 / 正面 1.25。
**木头在两个方向都不输泥土，容量还大一倍。** 泥土唯一的"优势"是它可以被草方块/菌丝/灰化土/泥巴轻易获得 —— 但木头同样满世界都是。
**建议**：把 `DIRT` 改成真正的"垃圾处理品"定位，让它**有一样东西是别人没有的**（把握：中）：
```
DIRT  容量 8 → 16（与 wood/cobble 齐平）
      特殊：泥土是唯一【允许把任意极性倒进去而不触发极性冲突反噬】的材质
            （即 RitualEffects.java:95-119 的"两股对立情绪相撞"对 dirt 中心不生效）
```
这条改动的依据在代码里：`RitualEffects.java:95-119` 的极性冲突惩罚**非常严厉**（清空法杖 + 反胃 400 tick + 中毒 200 tick）。给它开一个"泥土豁免"的口子，泥土就有了明确用途，且不动任何倍率数字。

### ★☆☆ 问题 5：仪式注入完全不吃"输出系数"，导致等级表的另一半形同虚设（把握：**高**）

**事实**：`outputRatioForTier` 只出现在 `EmotionStaffItem`。仪式注入公式是 `外围注入 × 中心注入 × 偏好`，**没有输出系数**。
后果：**中心雕像等级的价值只剩"注入比例 0.50/0.75/0.90/1.00"这一条**，等级表里那半张"输出 80/90/100/120 %"只影响"挥杖打怪时给几秒生命恢复/虚弱"（`EmotionStaffItem.java:157`：`duration = clamp(power × 20, 20, 600)`，上限 30 秒）。

**这条不算 bug，但它意味着**：玩家评估一尊雕像时，**输出系数几乎不进入决策**，因为它跟"攒情绪→绽裂→拿心绪"的主循环无关。
**建议**（把握：中）：如果作者希望等级表两半都有意义，可以给仪式注入加一个"中心输出等级的小额加成"，例如
```
lossss = 外围注入 × 中心注入 × 偏好 × (0.85 + 0.15 × 中心等级)   // 0级 ×0.85，3级 ×1.30
```
**注意**：这会**普遍提高**注入量（0 级中心反而被削弱），需要同时把基础倍率整体下调，否则 §7 的极值会往上走。**我不推荐在没有整体重算的情况下动这条。**

## 9.2 是否存在支配策略

**有，而且很明显。**

### 支配策略 1：**永远用升华 + 紫颂花外围 + 紫颂花中心 + 只记"空无"记录**（把握：**高**）

| 对比项 | 升华 + 紫颂花 | 沉坠 + 末地岩石/紫珀 |
|---|---|---|
| 最大倍率 | **12.96** | 11.03 |
| 外围雕像数 | 4 | 4 |
| 外围方块 | 紫颂花（末地，一棵树砍一堆） | 末地岩石 / 紫珀砖 |
| 中心方块 | 紫颂花 | 紫珀砖（要烧紫颂果） |
| 记录获取 | 末地群系（空无）或霜寒 | 同 |
| **结论** | **成本更低、收益更高** | 全面劣势 |

只要玩家知道这条，**沉坠仪式就成了"没有存在理由"的选择**（除了它产出负面心绪这条设定上的理由）。

### 支配策略 2：**外层"下界"是万能次优解**（把握：**中高**）

下界组合 `下界原木 × 下界原木` 对下界记录 = **5.062**，而且：
- 下界原木容量 32（比木头 16 大一倍）；
- 下界记录极易获得（下界群系 + `soul_sand`/`basalt_deltas`/`crimson_forest` 全归下界属性）；
- 下界岩石（9 条材质）容量 32，是沉坠侧的对应物。

**问题**：下界组合的**上限虽然低于紫颂花，但它的"下限"高得多**（不需要末地）。这让"紫颂花"变成"毕业装"，而下界变成"70 % 效果、30 % 成本"的常态选择 —— **这其实是个健康的设计**，只要紫颂花不再断层 2.56 倍。**所以问题 1 的修正是解锁整个体系的关键。**

### 支配策略 3（**最需要警惕的**）：**紫珀砖是所有"负面杖"的默认中心**（把握：**高**）

`purpur` = 等级 3（注入 100 %）+ 容量 32 + 属性空无 + 负面 1.75 + 无条件 1.00。
作为中心：负面峰值 `1.75 × 2.00(空无同类) × 1.00 = 3.50`，且**注入比例 1.00 是全场最高**。
对比 `end_rock`（等级 2 / 0.90 / 容量 48 / 负面 1.75 × 2.00 = 3.50）：
- 紫珀砖：`0.90(外围) × 1.00(中心) × (3.50 × 3.50) = 11.025`
- 末地岩石：`0.90 × 0.90 × (3.50 × 3.50) = 9.922`

**紫珀砖用更小的容量换到了 11 % 更多注入** —— 这是**正确**的权衡（容量小 → 更容易超容量 → 更快绽裂）。
**但它的"共享存储"特性（`sharedStorage()`）在仪式路径上找不到调用点**，所以目前紫珀砖实际就是**"3 级、容量 32、负面 1.75 的空无中心"**，没有任何独特机制。**建议把"共享存储"真正接上，否则它就是一个纯数值件。**

## 9.4 三种仪式的收益/成本是否失衡

| 仪式 | 结构 | 消耗 | 时长 | 直接产出 | 间接产出 |
|---|---|---|---|---|---|
| **升华** | 中心 1 + 外围 4（木类，同类） | 1 条记录 | 30 秒 | 法杖 +1~415 点（正面） | 可绽裂 → 心绪 |
| **沉坠** | 中心 1 + 外围 4（石类，同类） | 1 条记录 | 30 秒 | 法杖 +1~353 点（负面） | 可绽裂 → 心绪 |
| **绽裂** | 中心 1 + 外围 8（任意，朝外） | **不消耗记录** | （见下） | 心绪 + 按含量×3 | 装不下 → 经验 |

**时长问题（把握：中）**：`OUTER_RITUAL_TICKS = 600` 只用在升华/沉坠（`RitualEffects.java:211`）。**绽裂没有时长常量**，`burst()` 是**立即结算**的（`RitualEffects.java:274-385`，方法内没有任何 `startRitual`/延时调用）。
**所以绽裂是"零时长"的** —— 它只要 8 尊外围雕像（比升华/沉坠多 4 尊）作为成本。

**失衡分析**：

- **升华/沉坠**：成本 = 1 条记录 + 30 秒 + 5 尊雕像。收益 = 1~415 点情绪。
- **绽裂**：成本 = 8 尊雕像（一次性建设，可复用）+ 0 秒 + 0 条记录。收益 = 最多 4980 点心绪 + 1460 经验。

**绽裂不消耗记录**这件事本身是对的（它是"释放"不是"收集"），但它导致的后果是：

> **绽裂的边际成本 ≈ 0**（雕像建好之后），而它的产出直接消耗"存储容量"这个**每玩家上限 1000 点（6×100 + 4×100）的资源**。
> 也就是说：**绽裂的瓶颈在心绪存储，不在仪式本身。**

这个设计是**自洽的**，但它带来两个具体问题（见 9.5、9.6）。

**建议**（把握：中）：
1. **给绽裂一个时长**（例如 `BURST_TICKS = 200`，10 秒），让"多摆 4 尊雕像"这个成本更实在，也给"气球爆开"的动画留时间。
2. **把绽裂的入场券从"超容量 1 点"改成"超容量 50 %"**，理由见 9.6。
3. **让升华/沉坠的成本结构对称**：目前沉坠的产出天生低 15 %（问题 2），**建议通过调 `END_ROCK`/`CHORUS` 的极性层拉平，而不是通过增加沉坠的奖励**。

## 9.5 心绪 100/类的上限与绽裂 ×3 的产出是否匹配

**答：严重不匹配，而且是双向的**（把握：**高**）。

### 方向一：上限太低，一次"满溢小杖"就能顶满

`EmotionMoodStore.CAPACITY = 100`（每类），**存储总容量** = 正面 600 / 负面 400。
而 §8.2 显示：**一次满溢（容量+1）的绽裂**产出心绪总量从 27（泥土杖）到 387（灵魂杖）。
- 泥土杖：27 点，分 6 份每份 4 → **存储毫无压力**（吸收率 100 %）。
- 灵魂杖：387 点，分 6 份每份 64 → **存储也毫无压力**（384 ≤ 600）。
- **只有含量 > 200 时才开始溢出。**

**但**：§6.8 的算例 7 里，一条记录就能把杖灌到 415 点 → 绽裂产出 4980 点 → **存储只装 600，其余 4380 变 1460 经验**。
**换句话说：一套紫颂花结构 + 一条空无记录，第一次绽裂就把六种正面心绪全部顶满到 100。**

**这是"一下就顶满"的典型。** 之后玩家再绽裂，**装不下的部分全变经验**。

### 方向二：上限太高（相对低容量杖的产出），导致整数截断浪费

| 杖 | 满溢含量 | 心绪总量 | 每份 | 理想分配 | 与总量之比 |
|---|---|---|---|---|---|
| dirt | 9 | 27 | 4 | 24 | **88.9 %**（丢 3 点） |
| wood | 17 | 51 | 8 | 48 | **94.1 %**（丢 3 点） |
| soul | 129 | 387 | 64 | 384 | **99.2 %**（丢 3 点） |

**整数截断的损失很小（≤ 11 %）**，所以这一侧不是大问题。**真正的问题是方向一。**

### 建议（把握：高）

| 建议 | 具体数值 | 理由 |
|---|---|---|
| **A（推荐）** | 把转换比从 **×3 → ×1.5**，同时每类上限 **100 → 150** | ×1.5 让 415 点含量 → 622 点心绪 → 分 6 份每份 103（刚好在 150 之下）；存储总容量 900，**一次顶不满，两次才满**。玩家的"攒→炸→撒"有了 2 次节奏 |
| B | 保持 ×3，每类上限 **100 → 300** | 存储总容量 1800，415 点含量 → 1245（正面）也能装下。但 300 这个数字太整，"装满"的成就感被拉长 |
| C | 保持 ×3 和 100，但给每份加"软上限"：`每份 = min(每份, 40)`，超出部分直接转经验 | 改动最小，且天然压制紫颂花断层的影响。**但会让"大容量杖"失去意义** |

**我推荐 A**，并配套：**绽裂的 `totalMood = round(amount × 3.0)` 改成 `round(amount × 1.5)`**（`RitualEffects.java:305`），`EmotionMoodStore.CAPACITY = 100 → 150`（`EmotionMoodStore.java:30`）。

## 9.6 溢出转经验（÷3）会不会变成刷经验的手段

**结论：作为"刷经验引擎"效率很低；但作为"无上限的溢出出口"有一个结构性问题。**（把握：**高**）

### 效率测算

`溢出心绪 ÷ 3 = 经验`，而 `心绪 = 法杖含量 × 3 × 外围偏好`。**两个 ×3 ÷3 互相抵消**，所以：

**每 1 点法杖含量 → 最多 1.33 点经验**（满外围偏好时；无偏好时是 1:1）。获得这些含量需要：
- **1 条记录**（`amountFrom` 8~32，乘以份额 0~1 → `total` 2~32）
- **一次 30 秒仪式**
- **一套 5 尊雕像的结构**

**最乐观刷经验路径**：
```
无限循环：外围 4× 紫颂花 + 中心紫颂花 + 空无记录 → 每条记录 415 点注入
          → 攒 1 条就溢出 → 绽裂 → 600 点心绪（已满）+ 约 138 点经验
```
即 **每条记录 + 30 秒 ≈ 138 点经验**（约 4.8 级）。
对照 Minecraft 常规经验农场（刷怪塔 ~1000+ 经验/分钟、烧炼机 ~1 级/分钟），**这个效率并不夸张**。
**而且**：需要 5 尊紫颂花雕像 + 8 尊绽裂雕像 + 稳定的空无记录来源（末地或霜寒群系）——**门槛比刷怪塔高得多**。

**所以：不是"刷经验的手段"，但确实是"多余的杖含量可以换经验"的好设计。**

### 结构性问题：**经验产出没有上限，且 `capacity` 是载荷字段**

`RitualEffects.java:342` 是裸的 `int xp = shortfall / 3;`，**没有任何上限**。
而 `shortfall` 由 `payload.amount()` 决定，`amount` 是**累加**的（`RitualEffects.java:192`：`payload.amount() + injected`）。

**如果 `capacity` 可以被设成很大的值**（`EmotionPayload` 的 `capacity` 是数据组件字段），那么"攒一根巨大容量的杖 → 一次绽裂 → 巨量经验"就是可能的。
**我检查了通往绽裂的路径**：
- `GuideBookItem.java:344` 创建法杖时用的是 `kind.capacity()`（**受 19 种材质表约束，最大 128**）
- 释放清空用 `payload.drained()`（**保留 capacity**，`:91-94`）—— 所以**旧杖的 capacity 会跟着走，不会被重置为 0**
- `effectiveCapacity()` 在 `capacity <= 0` 时回落到 `kind.capacity()`（`:100-108`）
- **我未核对**：是否有命令 / NBT 编辑 / 创造模式物品能直接写入 `capacity`

**若存在这样的路径**，则 `xp = amount/3` 无上限 —— 一次绽裂可以给出任意经验。**这一条我标"未核对"，但值得作者确认。**

### 入场券判定的边角（把握：**中**）

`RitualEffects.java:283`：
```java
if (payload.amount() <= payload.effectiveCapacity()) { ...拒绝... }
```
**只有这一条下界判定，没有 `capacity > 0` 的检查。**

我追了一遍 `capacity` 的所有来源，**结论是这里暂时不可被利用**（如实说明，不夸大）：
- 仪式产出的杖 `capacity = kind.capacity()`，恒 > 0（`GuideBookItem.java:344`）。
- `payload.drained()`（释放清空）**保留 capacity**（`EmotionPayload.java:91-94`），所以"用过的杖"capacity 不会归 0。
- `effectiveCapacity()` 只在 `capacity <= 0` 且 `kindId` 为空时返回 0（`EmotionPayload.java:100-108`），
  而这时 `amount` 也必然为 0 → `0 <= 0` → **被拒绝** ✅。

**所以这不是漏洞，只是防呆不够**：`kindId` 为空、`capacity` 为 0、`amount` 恰好为 0 时靠 `<=` 兜住，
一旦将来有人让 capacity 变成**负数**（例如某个新写入路径），`amount <= capacity` 会恒真 → 反而**拒绝一切**，或者被反向绕过。**建议加一行显式守卫。**

**真正需要改的是门票门槛，不是这个边角**：

3. **"极小极性的杖"根本不划算**：`capacity = 32`（紫珀砖），`amount = 33` → 满足入场券。
   `totalMood = 99`，`per = 16`，**六种正面心绪各得 16 点** → 存入 96 点。**零经验**。
   → 玩家为了"清掉 33 点"付出的成本（1 条记录 + 30 秒 + 4 尊雕像）**远超收益**。
   → **这不是漏洞，是"不划算"** —— 但它暴露了"超容量 1 点"这个门槛毫无意义。

**真正的结构性问题**：**绽裂的入场券（超容量 1 点）太宽松**，导致：
- 玩家**不需要**"升华/沉坠反复注入"就能绽裂 —— 只要多灌 1 点。
- 这与 `癫狂构想-第二阶段实施方案.txt:229-230` 的设计意图（"法杖【超容量】正是绽裂仪式的入场券"，暗示需要"反复注入"）**在数值上脱节**。

### 建议（把握：高）

| 建议 | 具体改动 | 理由 |
|---|---|---|
| **A（推荐）** | `RitualEffects.java:283` 的判定改为 `if (payload.amount() < payload.effectiveCapacity() * 1.5) 拒绝`；并在 `payload.effectiveCapacity() <= 0` 时**直接拒绝** | 让"超容量"名副其实，同时堵住 capacity=0 的边角 |
| **B** | 经验产出加软上限：`int xp = Math.min(shortfall / 3, 60);` | 单次绽裂最多 2 级经验，杜绝"一根巨杖换 1000 经验" |
| **C** | 溢出不再转经验，改为"溢出部分按 1:1 存进一个**无属性标签**的溢出池"（上限另设，例如 200/类） | 保留"不浪费"的善意，但把经验彻底排除，避免任何刷经验联想。**需要新数据结构，成本最高** |

**我推荐 A + B 一起做。**

## 9.7 等级 0→3 的收益曲线是否平滑

**注入比例曲线是平滑的**（把握：**高**）：

```
0→1  0.50 → 0.75    +50.0 %
1→2  0.75 → 0.90    +20.0 %
2→3  0.90 → 1.00    +11.1 %
```
递减递增，符合"边际收益递减"。**这条没问题。**

**容量曲线是完全不平滑的**（把握：**高**）：

按等级看容量的实际分布：
```
0 级：8, 16, 16, 128    ← 包括全场最大和全场最小
1 级：24, 24, 24, 24, 24, 32, 32
2 级：32, 40, 40, 48, 48, 48
3 级：32, 56             ← 32 与 1 级并列，56 也没超过 2 级太多
```

**问题点**：

| 现象 | 具体 | 把握 |
|---|---|---|
| **`purpur`（3 级 / 容量 32）容量倒挂** | 3 级的紫珀砖容量 **32**，比 2 级的 `nether_brick`（40）和 `end_rock`（48）都小，和 1 级的 `nether_rock`/`nether_wood` 持平。**"升到 3 级，容量反而缩水"** | **高** |
| **`soul`（0 级 / 容量 128）断层** | 128 是次高（56）的 **2.3 倍**，而它只有 0 级。这让"容量"和"等级"彻底脱钩 | **高** |
| **`dirt`（0 级 / 容量 8）断层** | 8 是最低，木头/圆石同 0 级都是 16。泥土**容量也只有一半** | **高** |
| **1 级内部有 24 和 32 两档** | `nether_rock`/`nether_wood` 是 32，其余 1 级是 24 —— **同为 1 级容量差 33 %** | **中** |
| **"跳级式强点"是否存在** | **注入比例上没有跳级**（最陡是 0→1 的 +50 %）。**但容量上有**：`soul` 0 级拿 128 是"跳级"；`purpur` 3 级拿 32 是"跳级反向" | **高** |

**建议（把握：高）**：把容量做成**"等级为主 + 材质特性微调"**的两层结构，而不是现在这样一列自由数字。

```
基准容量（按等级）：0 级 = 16   1 级 = 32   2 级 = 48   3 级 = 64
材质微调：         ±0 或 ±8 或 ×2（仅灵魂）
```
**具体重排建议**：

| 材质 | 现容量 | 建议容量 | 理由 |
|---|---|---|---|
| `dirt` | 8 | **16** | 与 wood/cobble 齐平，它靠"极低倍率"体现弱，不靠容量 |
| `wood` | 16 | 16 | 不动 |
| `cobble` | 16 | 16 | 不动 |
| `sandstone`/`red_sandstone`/`snow`/`ice` | 24 | **32** | 与 1 级基准对齐 |
| `nether_dirt` | 24 | 32 | 同上（同时解决 §9.3 的"被下界岩石支配"） |
| `nether_rock`/`nether_wood` | 32 | 32 | 不动 |
| `iron` | 32 | **48** | 2 级基准；配合 §9.1 问题 4，铁降乘数、升容量 |
| `gold` | 40 | 48 | 2 级基准 |
| `emerald` | 48 | 48 | 不动 |
| `nether_brick` | 40 | 48 | 2 级基准 |
| `end_rock`/`chorus` | 48 | 48 | 不动 |
| `diamond` | 56 | **64** | 3 级基准 |
| `purpur` | **32** | **64** | **修掉容量倒挂**（这是最该改的一条） |
| `soul` | **128** | **96** 或 **64** | 保留"容量专精"身份但不做 2.3 倍断层 |

改完后：容量随等级严格单调（16 < 32 < 48 < 64），**唯一例外是灵魂**（0 级/96，用"等级低但容量大"作为它的身份）—— **这个例外是有意义的，保留它。**

```
沉坠最大倍率：0.90 × 1.00 × (3.60 × 3.60) = 11.66   ← 会反超升华，需要再平衡
```
**所以 #4 不能单独做，必须和 #1 一起做，并且要复查沉坠侧。**
**我的建议是改成：**
```
CHORUS   正面 2.00 → 1.80    负面 1.50 → 1.30
PURPUR   负面 1.75 → 1.70    正面 1.00 → 1.10
END_ROCK 负面 1.75 → 1.70    正面 1.00 → 1.05
NETHER_ROCK 负面 1.50 → 1.55 正面 0.75 → 0.85
```
则：
- 升华最大：`0.90 × 0.90 × (3.60 × 3.60) = 10.50` → 32 点记录 **336 点**
- 沉坠最大：`0.90 × 1.00 × (3.40 × 3.40) = 10.40` → 32 点记录 **333 点**
- **两者基本持平（差 0.9 %），且都落在"单条记录 300–350 点"的健康区间**（当前是 415 vs 353，差 17.6 %）。
- 下界组合（下界原木 × 下界原木 + 下界记录）：`0.75 × 0.75 × (3.00 × 3.00) = 5.06` → **162 点**。
  **最优/次优 = 336/162 = 2.07 倍** —— 仍然有优势但不再是断层，玩家可以"用末地装打 2 倍收益，或用下界装稳定拿一半"。**这是可接受的取舍。**

# §10 复核清单（给作者当核对工具用）

## 10.1 一句话公式链

```
记录.ratio ──floor(×4)──▶ 档位 0/1/2/3 ──▶ amountFrom = 8/16/24/32
                                              │
                          ┌───────────────────┴──────────────────┐
                          │  升华取 ratio 份 · 沉坠取 (1−ratio) 份 │
                          └───────────────────┬──────────────────┘
                                              ▼
                                       total = round(...)
                                              │
        total ≤ 0 ──▶ 【失败】消耗记录，不注入，不播动画
                                              │
                                              ▼
  注入 = max( 1, round( total × 外围注入比例 × 中心注入比例 × 偏好 ) )
                                              │
                    偏好 = 外围倍率 × 中心倍率
                    单层倍率 = 属性层(1.00~3.00) × 极性层(0.50~2.00) × 无条件层(1.00/1.20)
                                              │
                                              ▼
                          累加进法杖（可超容量；满/超容量时禁止再注入）
                                              │
                          超容量 + 纯单一极性 ──▶ 绽裂
                                              │
              心绪总量 = round(含量 × 3)，再 × 外围单层偏好（只一层）
                          每份 = 心绪总量 // (正面 6 / 负面 4)，每条 ±20 % 随机
                                              │
                          每类封顶 100，装不下的 ÷3 变经验
                                              │
                          溢出转经验：约 1 点杖含量 → 1 点经验（满偏好时 1.33）
```

## 10.2 容易算错的五个地方

1. **偏好是"外围一层 × 中心一层"，不是四次方，也不是"外围四尊各算一次"。** 外围四尊强制同类，所以只算一尊。（`RitualStructure.java:184-188` 强制 `kind != k` 就 `return null`）
2. **属性偏好里没有"输出系数"。** 输出系数只在挥杖时用。
3. **`Math.max(1, …)` 的保底 1 点，只在"仪式成功"时生效。** `total ≤ 0` 是**另一条失败路径**，那条是 0 点。
4. **绽裂的偏好只乘一次（外围），且用的是"法杖载荷里的属性"。** 中心雕像完全不参与（`RitualEffects.java:306-316`）。
5. **`每份 = boosted // pool.size()` 是整数除法，然后是 `max(1, round(per × (0.8 + rng × 0.4)))`。** 所以 `boosted` 的零头会被丢掉（例如 boosted=51、6 份 → per=8、只发 48）。**随机浮动是在 `per` 之上，不是在 `boosted` 之上。**
